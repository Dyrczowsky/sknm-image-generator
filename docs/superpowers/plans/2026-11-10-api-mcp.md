# API + MCP for AI-generated images — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An external AI (via MCP) or any HTTP client sends template + texts + photos and gets back a public PNG link; the image is pixel-identical to the app's export and lands in shared history marked "AI".

**Architecture:** A separate Cloudflare Worker (`api/`) authenticates the call, fetches photos, opens the app's hidden `/render` page in Cloudflare Browser Rendering and calls `window.sknmRender(input)`. The page validates input with the app's own code, renders the poster with the real components, rasterises it with the real export code and returns PNG + snapshot + history row. The Worker uploads photos and PNG to Supabase and inserts the history row with the service-role key. The Worker never imports React/app components; the only shared artefacts are a generated `templates.json` and type-only imports.

**Tech Stack:** React 19 + Vite (existing app), Cloudflare Workers + Browser Rendering (`@cloudflare/puppeteer`), Workers Rate Limiting binding, Supabase REST/Storage via `fetch` (no supabase-js in the Worker), MCP Streamable HTTP (hand-rolled, stateless, JSON responses), vitest, oxlint.

**Spec:** `docs/superpowers/specs/2026-11-10-api-mcp-design.md`

## Global Constraints

- Code comments, error messages for users and docs in **Polish**, like the rest of the repo.
- Shapes: only `square` (1080×1080) and `story` (1080×1920). No banners, print, PDF.
- Photos: JPEG/PNG only (detected from bytes, not from the declared mime), ≤ 5 MB each (`MAX_ASSET_BYTES`), ≤ 6 per call, ≤ 15 MB total *(plan's call: keeps the CDP payload sane)*.
- Snapshot ≤ 65536 bytes (`octet_length(snapshot::text)`); oversized → error, never truncate.
- Text field ≤ 2000 characters; agenda ≤ 20 items.
- `titleScale` / `textScale` in 0.7–1.3.
- Photo refs: `<sha256>.(jpg|png)` computed with `refFor` from `src/assets/hash.ts` over the **original bytes**.
- Photo bucket `sknm-poster-assets` (existing, private); output bucket `sknm-ai-images` (new, public, `image/png`, 10 MB), object name `<YYYY-MM-DD>/<uuid>.png`.
- Worker secrets: `SKNM_API_KEY`, `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`; var `RENDER_URL` = `https://sknm.dyrczowsky.win/render`.
- Auth: `Authorization: Bearer <key>` or MCP path `/mcp/<key>`; constant-time compare; the key never appears in logs or error bodies.
- `service_role` key must never reach the app build (`VITE_*`) or the browser page.
- Render timeout 30 s; rate limit 10 calls / 60 s (global key).
- Deploy keeps the existing rule: the job holding `CLOUDFLARE_API_TOKEN` runs no repo code.

## Review Focus

1. **Photo URL that isn't an image** (Google Drive share page, HTML login wall, redirect to a 404) → error `photo_not_image` naming which photo, not a broken render. Test in Task 7.
2. **App not yet deployed with `/render`, or an old cached build** (`window.sknmRender` never appears) → error `render_unavailable` within the timeout, not a hang. Test in Task 8.
3. **`story` on a layout without `storyShape`** → square poster on a tall canvas, exactly like the app's Story export (`shapeFor('story', …, false) === 'square'`, format `story`). Test in Task 3.
4. **AI omits fields** → omitted text fields are hidden, not filled with sample placeholder text (`PLACEHOLDERS`), except `badge`/`badge2`, which keep the layout's default label. Test in Task 3.
5. **Partial failure after render** (PNG upload or history insert fails; photo already exists → 409) → 409 counts as success; any other failure returns an error and no history row points at a missing PNG. Test in Task 8.
